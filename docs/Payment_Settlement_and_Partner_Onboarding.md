# PitNow 결제·정산 및 파트너 입점 운영안

- 작성일: 2026-07-31
- 문서 상태: Toss·세무 검토 전 권장 초안
- 관련 문서: `docs/Payment_MVP.md`

> 이 문서는 결제 API 구현 설명이 아니라 실제 돈의 흐름, 중개수수료,
> 정비소 계약과 입점 서류를 정리한다. 최종 구조는 Toss Payments의 계약
> 답변과 세무 검토를 받은 뒤 확정한다.

## 1. 결제 구조의 기본 원칙

1. 실제 SELF·SHOP 서비스 판매자는 정비소다.
2. PitNow는 예약·결제를 중개하고 중개수수료를 받는다.
3. 정비소의 정비 매출과 PitNow의 중개수수료 매출을 구분한다.
4. 결제, 영수증, 환불, 세금계산서, 정산서가 같은 구조를 설명해야 한다.
5. 소비자가 결제 전에 실제 판매자와 취소·환불 조건을 알 수 있어야 한다.

## 2. 권장 결제 구조

### Phase 1. 정비소 1곳 파일럿

권장안:

- 정비소가 Toss 가맹점 계약 주체가 된다.
- PitNow 결제 화면에서 해당 정비소 MID로 결제한다.
- 카드 매출전표의 판매자도 정비소로 표시한다.
- Toss는 정비소 계좌로 판매대금을 정산한다.
- PitNow는 월별 완료 거래를 집계해 정비소에 중개수수료를 청구한다.

예시:

| 항목 | 금액 |
| --- | ---: |
| 사용자 결제액 | 50,000원 |
| PitNow 중개수수료 10% | 5,000원 |
| 중개수수료 부가세 10% | 500원 |
| 정비소가 PitNow에 지급할 합계 | 5,500원 |

위 예시는 `중개수수료 10%, VAT 별도`일 때의 예시다. 실제 수수료 기준과
부가세 처리는 세무 검토 후 계약서에 확정한다.

PG 결제수수료는 정비소 판매 매출에 발생하는 비용이므로 Phase 1에서는
정비소 부담을 기본안으로 한다.

장점:

- 실제 판매자와 카드 매출 명의가 일치한다.
- 정비소 매출과 PitNow 매출 구분이 비교적 명확하다.
- 입점 정비소 한 곳으로 시작할 때 고정 정산비 부담이 작다.

단점:

- 정비소마다 PG 계약과 MID가 필요하다.
- 서버에서 정비소별 키를 안전하게 관리해야 한다.
- 취소·부분취소도 해당 정비소의 계약·키로 처리해야 한다.
- PitNow가 월 수수료를 별도로 회수해야 한다.

### Phase 2. 여러 정비소로 확장

입점 정비소와 거래량이 늘면 Toss 지급대행을 검토한다.

예상 흐름:

```text
사용자 결제
  -> Toss PG 승인
  -> 플랫폼 정산 재원 반영
  -> PitNow가 셀러별 지급액 계산
  -> Toss가 정비소 계좌로 지급
  -> PitNow 수수료와 환불·보류액은 정산 원장에 별도 기록
```

Toss 지급대행은 결제 순간 두 계좌로 동시에 금액을 나누는 기능이라기보다,
가맹점 정산대금을 재원으로 등록된 셀러에게 바로지급 또는 예약지급하는
서비스에 가깝다.

- Toss 지급대행 기본 정책:
  https://www.tosspayments.com/blog/articles/30365?from=recommended
- Toss 셀러 등록·지급대행 API:
  https://docs.tosspayments.com/reference/additional

공개 안내 기준으로 월 고정 이용료가 있으므로, 소규모 파일럿에서는 현재
계약 요금을 확인한 뒤 경제성을 판단한다.

- Toss 지급대행 신청 안내:
  https://www.tosspayments.com/blog/articles/30355?from=recommended

### 권장하지 않는 구조

정비소가 전체 결제액을 받은 뒤 각 예약마다 자율적으로 수수료를 송금하는
구조는 권장하지 않는다.

문제:

- 미납·지연 가능성
- 예약별 입금 대사 어려움
- 취소·부분환불 후 수수료 재계산 어려움
- 정비소가 늘어날수록 운영 비용 증가

Phase 1에서 월 수수료를 청구하더라도 월 정산서, 세금계산서, 지급기한,
연체 조항과 서비스 이용정지 기준을 계약으로 고정한다.

## 3. 초기 중개수수료 제안

### 권장 시작안

- 수수료 기준: 완료·확정된 순결제액
- 수수료율: 10%
- 부가가치세: 별도
- 정산 주기: 월 1회
- 파일럿 혜택: 첫 1~2개월 감면 또는 면제 가능

`순결제액`은 다음과 같이 정의한다.

```text
순결제액 = 승인 완료 결제액 - 취소액 - 환불액
```

수수료가 부과되는 항목:

- 완료된 SELF 예약금
- 완료된 SHOP 패키지 결제
- 플랫폼에서 결제된 추가 정산
- 정비소에 귀속되는 노쇼·취소 수수료

수수료가 부과되지 않는 항목:

- 전액 취소·전액 환불
- 결제 실패
- 정비소 귀책으로 전액 반환된 금액
- 플랫폼 밖에서 별도로 합의·결제한 추가 정비

부분환불은 환불 후 남은 실제 결제액을 기준으로 수수료를 다시 계산한다.

### 수수료 확정 전 검토할 내용

- SELF와 SHOP에 동일한 수수료율을 적용할지
- 광고·프로모션 비용을 누가 부담할지
- 카드 PG 수수료를 누가 부담할지
- 쿠폰 할인액을 누가 부담할지
- 노쇼 수수료에 플랫폼 수수료를 부과할지
- 사후정산 결제도 동일한 수수료율을 적용할지

초기에는 복잡한 차등 요율보다 단일 10%가 운영과 설명에 유리하다. 거래량과
파트너 반응을 확인한 뒤 SELF·SHOP 차등 요율을 검토한다.

## 4. 월 정산 예시

| 항목 | 금액 |
| --- | ---: |
| 해당 월 승인 완료액 | 2,000,000원 |
| 취소·환불액 | -200,000원 |
| 순결제액 | 1,800,000원 |
| 중개수수료 10% | 180,000원 |
| 수수료 VAT | 18,000원 |
| 정비소 청구액 | 198,000원 |

월 정산서에 포함할 항목:

- 정산 대상 기간
- 예약 ID
- 예약 유형 SELF/SHOP
- 승인 결제액
- 추가 정산액
- 취소·환불액
- 순결제액
- 적용 수수료율
- 중개수수료
- 부가가치세
- 최종 청구액
- 이의제기 기한
- 지급기한

## 5. 정비소와 체결할 계약

### A. 파트너 입점 계약

필수 조항:

- PitNow와 정비소의 역할
- 정비소가 실제 서비스 판매자·제공자라는 점
- 허용된 SELF·SHOP 서비스 범위
- 정비소 정보의 정확성 유지 의무
- 시설·리프트·장비 안전관리
- 정비 관련 자격·등록 유지 의무
- 영업배상책임보험 등 보험 유지
- 사용자·차량 개인정보 처리
- 사고와 민원 발생 시 협조
- 서비스 품질 기준
- 계정 보안
- 계약 기간, 해지, 이용정지

### B. 수수료·정산 부속합의서

필수 조항:

- 중개수수료율
- VAT 포함·별도 여부
- 수수료 산정 기준
- PG 수수료 부담
- 정산 주기와 지급기한
- 취소·부분환불·차지백 처리
- 노쇼·취소 수수료 배분
- 세금계산서 발행
- 정산 오류 이의제기 기간
- 연체이자 또는 지연 시 조치
- 미납 시 예약 노출 중지·계약 해지
- 지급대행 도입 시 변경 절차

### C. 개인정보 관련 약정

정해야 할 내용:

- PitNow와 정비소가 각각 독립된 개인정보처리자인지
- PitNow가 정비소 업무를 위탁받아 처리하는 항목이 있는지
- 정비소에 제공되는 사용자 정보 범위
- 이용 목적과 보유기간
- 계정 접근 권한
- 유출·오남용 발생 시 통지와 대응
- 계약 종료 시 정보 삭제·반환

### D. 콘텐츠 사용 동의

- 정비소 상호·로고 사용
- 정비소 사진 공개
- 가격·패키지 정보 공개
- 사용자 리뷰 공개
- 계약 종료 후 콘텐츠 처리
- 타인의 저작권·초상권 침해 자료 업로드 금지

전자서명을 사용할 경우 서명자 신원, 서명 시각, 문서 버전, 원본 해시,
발송·열람 기록을 보존할 수 있는 서비스를 선택한다.

## 6. 입점 정비소에서 받을 서류

### 필수

- 사업자등록증
- 자동차관리사업 등록증
- 대표자 정보
- 운영 담당자 이름·연락처·이메일
- 사업자 명의 정산계좌 정보
- 파트너 입점 계약서
- 수수료·정산 부속합의서
- 시설·영업배상책임보험 증명
- 사업장 주소와 연락처

### 운영 정보

- 운영시간과 휴무일
- 베이 수
- 리프트 규격
- 허용 차종과 최대 중량
- SELF 제공 작업
- 정비사 작업 확인 제공 범위
- SHOP 패키지와 가격
- 취소·환불·노쇼 기준
- 업체 대표 사진과 갤러리

### 상황에 따라 추가

- 대표자가 아닌 담당자의 위임장
- 법인 등기 관련 자료
- 공동대표 관련 자료
- 계좌 예금주 확인 자료
- 안전점검·장비점검 기록
- 추가 인허가·자격 증빙

통장 사본은 반드시 필요한 경우에만 받고 접근 권한과 파기 시점을 정한다.
Toss의 계좌 유효성 검증을 사용할 수 있다면 사본을 장기 보관하지 않는
방향을 우선한다.

Toss 셀러 등록 API는 사업자번호, 대표자 정보와 계좌 정보를 사용해 셀러와
계좌를 검증한다.

- Toss 지급대행 셀러 등록:
  https://docs.tosspayments.com/reference/additional

## 7. 서류 수집·보관 원칙

- 개인 이메일·카카오톡에 서류를 장기 보관하지 않는다.
- 관리자 전용 업로드 또는 접근 제한 저장소를 사용한다.
- 파일 암호화와 접근 로그를 적용한다.
- 원본과 검토 상태를 구분한다.
- 서류 만료일과 갱신일을 기록한다.
- 계약 종료 후 법정·계약상 보존기간이 끝나면 파기한다.
- Partner-admin은 담당자별 계정을 사용한다.
- 공용 비밀번호를 전달하지 않는다.

권장 서류 상태:

```text
SUBMITTED -> REVIEWING -> VERIFIED -> EXPIRING -> EXPIRED
```

### 답변을 받을 때 반드시 기록할 것

- 상담 일시와 담당자
- 추천 계약 유형
- MID 소유 사업자
- 매출전표 표시 상호
- 실제 정산계좌
- 지급대행 필요 여부
- 월·건별 비용
- 보증보험
- 금지 또는 제한되는 정비 서비스
- 필요한 개발 변경
- 필요한 계약·KYC 서류

구두 답변만 받지 말고 가능한 경우 이메일 또는 제안서 형태로 남긴다.

## 9. Toss 답변 후 세무사에게 확인할 질문

```text
PitNow는 정비소 예약 중개 플랫폼이고 실제 서비스 판매자는 정비소입니다.
PitNow는 완료·확정된 거래액의 10%를 중개수수료로 받으려 합니다.

1. 정비소별 PG MID로 직접 결제할 때 PitNow는 중개수수료만 매출로
   인식하면 되는지 확인 부탁드립니다.
2. 중개수수료 10%에 VAT를 별도로 청구하고 정비소에 세금계산서를
   발행하는 구조가 맞는지 확인 부탁드립니다.
3. Toss 지급대행을 사용해 PitNow 계약 MID로 결제한 뒤 정비소에
   순액 지급할 경우, 총 결제액이 아닌 중개수수료만 PitNow 매출로
   입증하려면 어떤 계약과 정산 증빙이 필요한지 확인 부탁드립니다.
4. 취소·부분환불·노쇼 수수료의 세무 처리는 어떻게 해야 하는지
   확인 부탁드립니다.
```

## 10. 개발에 미치는 영향

### Phase 1 정비소별 MID

필요한 변경:

- partner별 payment merchant 설정
- partner별 client key와 secret key 보안 저장
- 예약 결제 준비 시 partner MID 선택
- 환불 시 원 결제 partner MID 사용
- 영수증에 실제 판매자 표시
- 월별 수수료 정산서 생성
- partner별 정산 상태 관리

키는 DB 일반 컬럼이나 브라우저에 평문으로 노출하지 않는다. 서버 전용 비밀
저장소와 접근 정책을 사용한다.

### Phase 2 지급대행

추가로 필요한 변경:

- Toss seller 등록
- partner KYC 상태
- 정산계좌 검증
- 예약별 seller·정산금 연결
- 지급 요청
- 지급 보류·실패·재시도
- 환불·차지백 정산 조정
- 지급대행 audit log

현재의 예약·결제 상태 모델과 별도로 정산 원장을 두는 것이 안전하다.

예상 핵심 테이블:

```text
partner_payment_accounts
partner_settlement_profiles
partner_settlement_periods
partner_settlement_items
partner_payouts
```

이 데이터 모델은 Toss 계약 구조가 확정된 뒤 설계한다.

## 11. 결정 게이트

개발을 바로 변경하지 말고 다음 순서로 결정한다.

1. Toss에 문의문 발송
2. 정비소별 MID와 지급대행 가능 여부 확인
3. 실제 비용·보증보험·계약 조건 비교
4. 세무사에게 매출 인식과 세금계산서 확인
5. 첫 입점 정비소와 수수료·정산 방식 협의
6. 결제 구조를 `docs/Decisions.md`에 확정 기록
7. DB와 결제 adapter 변경
8. Toss 라이브 QA

## 12. 현재 권장 결론

- 첫 정비소 1곳은 정비소 명의 PG 직접 결제를 우선 검토한다.
- PitNow는 완료·확정 순결제액의 10%, VAT 별도를 초기 제안으로 사용한다.
- 정비소가 PG 수수료를 부담한다.
- PitNow는 월 1회 정산서와 세금계산서로 중개수수료를 청구한다.
- 완전 취소·환불된 금액에는 수수료를 부과하지 않는다.
- 여러 정비소로 확장되고 수동 정산 비용이 커지면 Toss 지급대행으로 전환한다.
- 위 내용은 Toss와 세무 검토 전까지 최종 계약 조건이 아닌 협의 초안이다.
